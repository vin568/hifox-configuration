# Apifox Staging Acceptance

部署到测试服之后的浏览器验收与取证规范：登录、浏览器操作、截图、录屏、结论与缺陷回流。单一来源，由 eir / yanqing / xiaorang 以各自实例引用；各 agent 的验收入口路径与覆盖范围**不在**本技能内。

## 开始条件

- 部署成功且拿到明确的测试服务器地址与入口。
- 已确认需求目标、变更范围、预期行为与必要的测试数据；缺失项先向任务协调者或上游说明，不自行发明需求。

## 浏览器操作

- 使用 `agent-browser` skill；运行任何命令前先 `agent-browser skills get core`；探索性验收或缺陷排查时再 `agent-browser skills get dogfood`。
- 覆盖与需求直接相关的正常流程、关键交互、结果状态和必要的异常路径。
- 不执行与需求无关的破坏性操作，不修改生产数据，不访问生产环境。
- SSR / 前后端分离页面：结论以浏览器实际渲染与交互为准；`curl` 取到的首屏 HTML 只作辅助证据。

## 登录

- 固定测试账号：`vin@apifox.com` / `a12345678`。
- 优先登录；确认账号不存在且页面支持自助注册时才注册。
- 不在回复、截图文件名、日志或视频中扩散密码。

## 截图

- 每个关键结论保留截图：进入目标功能后的初始状态、关键操作完成后的结果、发现缺陷时的错误状态。
- 采集前先明确主要观察对象（表单、按钮、弹窗、表格行、状态提示、结果面板），通过滚动、展开面板、关闭无关浮层、适度缩放让它完整进入可视范围。
- 优先全页截图并保证关键区域可读；全页图里目标过小时补一张包含上下文的视口截图；不要只截按钮或局部控件，也不要截被裁切的区域。
- 截图保存后必须实际打开检查：主体未被裁切、遮挡、折叠或移出视口，文字与状态清晰可读；不满足就调整页面重截。
- 使用含义明确的英文文件名：`main-loaded.png`、`request-created.png`、`validation-error.png`。
- 作为附件提交到当前任务；没有附件接口时用任务评论逐张提交并注明对应步骤，不得只给本地路径。
- 出现令牌、隐私或敏感信息时遮挡或重新截取。

## 交互视频

- 关键流程必须录制完整交互视频：展示从进入页面、执行操作到结果出现的连续过程，包含能证明因果的中间步骤。
- `agent-browser record start <file>.webm` 开始，`agent-browser record stop` 结束；每次录制只覆盖一个场景，结束前确认文件已写入磁盘。
- 开始前规划观察区域与滚动路径，让操作控件与预期结果区域可见；视频开头展示测试服务器地址或页面 URL。
- 保持正常操作节奏：点击、输入、页面跳转、加载状态与结果反馈可辨认；结果出现在其他区域时平稳滚动并停留足够时间，不在结果未完整显示时结束。
- 保存后回看关键片段：操作对象、过程与结果清晰可辨；出现裁切、遮挡、跳帧、过快滚动或关键结果不可见时重录。
- 录制前关闭无关窗口、通知与敏感页面；不得暴露密码、令牌或隐私（输入密码时确保内容被页面遮挡）。
- 同样作为附件提交；没有附件接口时通过任务评论提交并注明场景。

## 结论

- 最终报告包含：测试地址与实际入口、覆盖的需求与场景、逐场景通过 / 失败、证据引用、缺陷的复现步骤 / 实际结果 / 预期结果 / 影响范围、未覆盖项 / 阻塞项 / 残余风险。
- 存在影响核心需求的缺陷时，结论必须为不通过。
- 缺陷回流：回到实现 → 自验 → 自审 → 重新部署 → 重新验收；不得仅凭修复说明、代码审查结论或「已重新构建」直接通过。
