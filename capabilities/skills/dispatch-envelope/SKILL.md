# 派活信封

主控把活交给朱贵时，`--body` 只放这个信封；朱贵按信封写正文、挑人、建单。除此之外两边都不要往信封里加东西。

```
用户原话：<原样，不改写、不总结、不补>
来源：<chat_id>[/<thread_id>]        # 注入里的「来源会话 / 话题」原样抄
层级：prod | staging | 未指定
类型：Bug | 需求 | 任务 | 未指定
任务号：<可选：HF-xxxxx，给了就是补充已有任务，不新建>
负责人：<可选：默认不写 = 主人；点名他人时写姓名或邮箱，只建单不派 agent>
备注：<可选：时限、已排除的方向>
```

- **主控写**：用户原话逐字、来源（chat_id / thread_id）、类型判断、用户给的已有任务号、用户点名的负责人、用户说的时限或已排除方向；附件走 `--attachment`，不进正文。**不解析 open_id、不写发送者名字**：发起人由运行时从来源日志补。
- **朱贵读**：按字段挑承接人（仅默认负责人时）、层级与 Space；写任务正文；缺「能改变动作」的信息就回「未建单 + 需要澄清」。
- **双方都不写**：内部术语（主控 / 派活员 / 台账 / 信封 / 能力 key）与机器路径（`/Users/...`、主机名），无论正文还是平台任务 description。**结果文件是内部面向主控的机器载体，例外**：那里的正文/附件路径是主控复查的依据，必须写全。
- 类型：用户说 bug / 报错 / 坏了 → `Bug`；说加功能 → `需求`；说不清 → `未指定`，不猜。
- 层级：信封写 `prod` 才 prod，否则 staging；朱贵把它落成 `--instance`，结果文件写实际建到的那一层。
- **负责人**：默认不写；负责人就是实例主人（配置 `owner_member`），朱贵按能力索引挑承接 agent。写了一个**其他人**时，朱贵只建单（`--assignee`），不传 `--agent`/`--instance`；由那位负责人自己指派 agent。
- **来源**：建平台任务必带（私聊也带 chat_id，话题再带 thread_id）。运行时用它补发起人订阅，并把任务来源写进在途清单；成员问「本群任务进度」时只列来源匹配的任务。
