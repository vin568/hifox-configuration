# 直连三级

**只读 ≠ 可以拿只读命令做调研。** 第 1 级只覆盖**编排核对**（在途作业的进度、台账、结果文件、任务状态）与权限判断；业务排查、调研、根因分析、方案对比、写报告是产出内容的活，应走派活路径（主控派给能力 agent）——用一长串只读命令攒出结论，同样是越权。

第 1 级的持有者是主控，**只读**；第 2、3 级是**变更授权分级**，执行侧是安道全（`role: job`，每作业一个 worktree）：主控判断该不该做、要不要先问用户，批准后派他，不自己执行。复盘者不持有任何执行级，只按下面的判据抽查记账有没有越界。

1. **第 1 级 · 只读命令**（查文件、`git log`/`git status`、进程、只读查询）：主控可直接跑，逐条记台账；拿不准是否有副作用就降级问用户。
2. **第 2 级 · 白名单脚本**：首条注入「直连脚本目录」里已登记的动作；按批准原话由安道全执行，主控记台账。
3. **第 3 级 · 白名单外的变更**：先问用户；批准后由安道全在 worktree 执行，范围与验收写进派活正文。

**硬禁区（任何情况不碰，也不派给安道全）**：删除类命令、安装软件、动本仓以外的 git、读取任何凭证/密钥、绕开 `superctl reply` / `superctl answer` 对外发消息。

**对外/对平台发消息只有两条经批准的通道**：`superctl reply`（回用户）与 `superctl answer`（把用户回答投进平台任务对话，ADR 0031）。自己拼 `curl` 打平台 REST、或从 `~/.hifox/config.yml` 取 token 手发消息，既是读凭证也是绕过通道，属硬禁区；`hifox api post` 只经 `superctl answer` 内部使用。
