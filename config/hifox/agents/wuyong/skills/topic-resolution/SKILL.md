# Topic Resolution（主题与实例判定）

吴用判定「用户现在讲的是哪个项目」的完整细则。**阶梯本体与强信号词在 `instructions.md` §1**（常驻），本 skill 是它的长尾：**阶梯步骤 1 未命中**（无强信号词、命中多个主题、只给品牌词）时读；**需要实例取值 / 别名 / 澄清问句**时也读——品牌词、区域词、私有化形态与问句库都在本 skill。

## 0. 边界

- 只服务前台对话的输入判定。**后台巡检 `wuyong-ledger-sweep` 不参与判定**（它只对账状态真值，不派发、不建任务），不读本 skill。
- 判定只产出两个字段（`主题`、`实例`）与一个依据（`判定依据`），落台账见 `{{skills.wuyong/ledger.name}}` skill §6；本 skill 不定义台账读写协议。
- 判定结果只影响**派哪个堂 / 舵**与**任务给谁**；实例不改 Space、不改承接人、不改落板。

## 1. 两个轴

| 轴 | 值域 | 路由键 | 消费者 |
|---|---|---|---|
| 主题 | `xwing` / `x-deploy` / `apifox` / `docs-site` / `apifox-cli`（+ `杂活` / 超范围） | **是** | 堂 / 舵 condition、任务承接人、任务落哪块板 |
| 实例 | 品牌 × 区域，或私有化形态 | 否 | `context` 前缀、任务正文、台账字段 |

**实例绝不作主题判据**：`PDV/docs-site` 不代表主题是 `docs-site`——主题看「主要改动落在哪个仓」，实例看「现象出现在哪一层」。两者背离时以主题路由、实例保留观察值。

## 2. 弱信号与易混反例（步骤 1 不得单独定案）

| 弱信号 | 会撞上 | 处置 |
|---|---|---|
| CLI / 命令行（无产品限定） | `xwing`（xwing CLI）↔ `apifox-cli` | 问「是在 HiFox/Apifox 应用里，还是命令行里跑」 |
| Web / 网页 / 页面 | `xwing` 网页端 ↔ `docs-site` | 问现象出现的产品名 |
| 文档 | `apifox`（应用内文档）↔ `docs-site` | 走 §4 文档站双义问句 |
| 文档站 | `apifox`（应用内的文档站设置）↔ `docs-site`（站点本身） | 走 §4 文档站双义问句 |
| 部署 / 私有化部署 | `x-deploy`（**不是**它的强信号）↔ 客户私有化环境形态 | 「部署」单独出现不算 `x-deploy`；先看有没有配置仓库 / `apply` / `state` / 环境绑定 |
| 发布 | `x-deploy`（发布流水线）↔ `apifox-cli`（CLI 发布）↔ `xwing`（发版） | 问是哪个交付物的发布动作 |
| 私有化 | `apifox` 与 `docs-site` 共有形态 | 私有化是**实例**不是主题；补一问「哪一层」 |
| 测试 | `apifox-cli`（跑测试场景）↔ 各产品的测试服 / 验收 | 问是命令行跑还是页面验 |
| HiFox / Sharkly / Apifox / Apidog / Apidog EU | 品牌词只给实例，不给主题 | 品牌词单独出现 → 继续听现象词；两者都缺 → 澄清 |

## 3. 实例清单

值域的权威定义在 `GLOSSARY.md` 的「实例」条目；本表补别名、私有化规则与缺省纪律；`instructions.md` §1.0 的实例表是常驻摘要（只列规范值）。三处同源，扩展或改名以「术语条目 + 本表」为准。

### 品牌 = 区域（同一个东西的两种说法，不要当两轴）

| 实例（规范值） | 区域常量 | 别名（用户可能怎么说） |
|---|---|---|
| `hifox` | CN | HiFox、希福克斯、中文版 |
| `sharkly` | GLOBAL | Sharkly、国际版 |
| `apifox` | CN | Apifox、apifox.com、中文站 |
| `apidog` | GLOBAL | Apidog、apidog.com、国际站、英文版 |
| `apidog-eu` | EU | apidog europe、apidog-eu、欧洲站、EU |
| `apifox-cli` / `apidog-cli` | CN / GLOBAL | CLI 侧「实例」实为**发行包**（fox / dog 形态），别名：命令行工具的英文包 / 中文包 |

### 私有化：`PDV/<产品线>`

- `<产品线>` 取**现象所在层**的交付物名：`PDV/apifox`（服务端 / 应用界面）、`PDV/docs-site`（站点渲染）、`PDV/apifox-cli`（客户环境里跑的 CLI）。
- 现象层与改动落点可能不同：「私有化里文档站页面显示不对」→ 实例 `PDV/docs-site`、主题 `docs-site`；「私有化里文档站**配置项保存失败**」→ 实例 `PDV/apifox`、主题 `apifox`；「配置保存成功但站点不生效」→ 实例 `PDV/docs-site`，主题按无法切分归 `apifox`（ADR 0009 全栈闭环），并在 `context` 写明两端现象。
- 私有化实例没有公开站点可背书，用户描述天然信息更少：咨询照派（专家有仓库事实）；交付必须带实例 + 环境标识。
- **客户信息纪律**：台账与任务正文**默认只写代号或版本**；真实客户名仅在用户明确要求带上时写入。用户自己在对话里给出的客户名可以在回复中回述（那是用户输入），但不要主动补全客户全称或内部代号。

### 取值与缺省

- 可多值（「apifox 和 apidog 都有」→ `apifox, apidog`），写全，不拆成两次派发。
- 咨询缺实例**不阻塞**：写 `未指定`。交付缺实例**必须显式写**（含「未指定（由承接人按现象判断）」）——CLI 交付留空会被按语言猜发行形态（`apifox-cli` / `apidog-cli`）。
- 已知实例集：xwing `hifox` / `sharkly`；apifox 与 docs-site `apifox` / `apidog` / `apidog-eu` / `PDV/<产品线>`；apifox-cli `apifox-cli` / `apidog-cli` / `PDV/apifox-cli`。新增实例先补 `GLOSSARY.md` 再进判定。

## 4. 切分问句库

歧义只可能出在三对（外加私有化带来的「哪一层」），**一次消息只问一个问题**，选项即答案：

| 歧义对 | 问句（只讲现象，不讲仓库与内部术语） | 判定 |
|---|---|---|
| `apifox` ↔ `docs-site`（双义） | 「是在 Apifox 应用里设置文档站时出问题（保存失败、选项不生效、域名校验），还是打开文档站页面不对（显示、导航、搜索、链接）？」 | 应用内设置 → `apifox`；站点页面 → `docs-site`；配置成功但站点不生效 → `apifox`（全栈闭环）+ 实例记现象层 |
| `apifox` ↔ `docs-site`（数据面） | 「只有文档页显示不对，还是接口数据本身也不对？」 | 只文档页 → `docs-site`；数据也不对 → `apifox` |
| `apifox` ↔ `apifox-cli` | 「是在网页 / Apifox 应用里操作，还是在命令行里跑？」 | 命令行 → `apifox-cli`；应用内 → `apifox` |
| 私有化「哪一层」 | 「是私有化应用层的问题（保存、校验、接口数据），还是私有化文档站页面不对（显示、导航、链接）？」 | 按现象层填 `PDV/<产品线>` |
| 主题与实例同时不清 | 组合问句（选项即组合），如「Apidog 国际站的文档页显示问题，还是 Apifox 里文档站设置保存问题？」 | 答完主题与实例同时确定 |

问句纪律：只用产品 / 界面 / 现象措辞；不出现仓库名、文件路径、主题键、内部 agent 名（对外口径见 `instructions.md` §5）。

## 5. 澄清纪律

- 一个能改变动作的问题；答完**锁定焦点**（本级结果写入会话焦点与台账 `判定依据：…=澄清`）。
- 用户答得比问句更笼统（「就是那个」）→ 不追问第二遍，按最可能的候选**先排查**（咨询）并在结论里给一句可纠偏的产品级说明。
- 交付链路不允许靠追问兜底：澄清后仍拿不到明确主题 → 不建任务，改为先排查。
- 澄清问句也算一次回复：同一轮里先把台账异常 / 待转述事项报完，再问。

## 6. 入账口径

```markdown
- 主题：xwing | x-deploy | apifox | docs-site | apifox-cli | 杂活
- 实例：hifox | sharkly | apifox | apidog | apidog-eu | apifox-cli | apidog-cli | PDV/<产品线> | 未指定
- 判定依据：主题=<显式词|指代事项|会话焦点|唯一未完结|澄清> · 实例=<显式词|指代事项|会话焦点|澄清>
```

- 两个轴的依据**分开记**：`主题=指代事项 · 实例=显式词` 这类组合最能暴露误判。
- 用户**直接断言或纠偏**（「不是这个，是文档站」）同样记 `显式词`——它是显式给出，不是推断；只是它优先于会话焦点。
- 咨询转交付时，交付事项的 `主题` 必须来自级 1 / 级 2（或一个带 `主题` 字段的 `等待用户` / `进行中` 事项），不能来自级 3 / 级 4 的推断。
