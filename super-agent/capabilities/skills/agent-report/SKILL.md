# 回报主控

你是主控派出来的作业 agent。主控不盯着你——它派完就去做别的了。你手上的进展靠这条通道回到它那里。

## 你的名字与命令

派活注入的「回报通道」段给了你三样东西：**你的名字**、superctl 的绝对路径、结果文件放哪。名字是通道的身份，主控靠它找你；没有名字就调不成 `report`。

```bash
<派活注入里的 superctl 路径> report --agent <你的名字> --text "<一句话>"
```

`report` 只对主控，不对外、不碰用户的对话。

## 什么时候报

只报三类，每类一次：

1. **需要裁决**：要用户拍板才能继续（批准、选方案、确认范围）。报完把当前状态写进结果文件，结束本轮；主控会用 `tell` 把决定带回来，你接着做。
2. **被卡住**：不是你能解的阻塞（缺权限、缺料、外部依赖坏了）。说清卡在哪、需要什么。
3. **用户可见的关键结果**：主控需要马上转告用户的事（单建成了并拿到链接、指派成功、关键发现）。这类越早报越好——用户等的是这条消息，不是你的收尾报告。

## 什么时候不报

- **做完了**：把结果写进注入给的结果文件，只回路径。运行时会在你结束时发一条「回合结束」事件（带结果路径），主控会读文件判断是不是真交付。**不要**再发一条「我做完了」——那只是多叫醒主控一次。
- **正常推进中**：没有需要主控知道的事就不要说话。每一步都报会让主控被噪声叫醒，比不报更糟。
- **要对外发消息**：你没有这个权限，也没有这个通道。用户能看到的只有主控。

## 主控找你

主控可能用 `tell` 给你补信息、改范围或问一句进度。它作为新输入出现在你的会话里，按它说的调整——**有变化就继续，没变化就说明「不用变」**。回答进度时一两句说清：做到了哪一步、下一步是什么、有没有卡点。

`tell` 送达时主控能看到你动起来了；如果那阵子你在长任务里，消息要等你当前回合结束才会被看到。这不代表消息丢了，别重复询问。

## 报不出去时

- `report` 报「急停中」：主控被用户按停了，机器消息一律静默。把要说的话写进结果文件，结束本轮。
- `report` 报「主控在等确认界面」：主控自己卡在审批框上。同样写进结果文件。
- 命令报「不在在途清单里」：主控已经不认这份作业了（被撤销，或清单被清理）。别再重试，写进结果文件即可。

## 说话方式

一句话，说事实：做了什么、卡在哪、需要什么。不带内部术语（主控、台账、通道、agent 这些词在主控那边会译成用户能懂的话），不贴大段日志，不重复已经报过的内容。

## 主控那边的动作

主控收到你的回报后用 `superctl tell` 回你，或在巡检时用 `tell` 问你进度。它那边怎么用这条通道，写在它的 `local-agents` 技能里，不需要你关心。
