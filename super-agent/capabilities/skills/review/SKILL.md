依次读 `[[skill:code-review]]` 与 `[[skill:test-review]]`，然后按下面的循环跑。

两把尺子的**完整流程都要跑**，不只是读它们的正文：code-review 的两个轴各开一个
独立子代理（每个全新上下文），test-review 建冻结台账并守轮次预算。少了这些，
「审过了」只是读过。

## 循环

1. **审**：按两份技能各自的流程审这一版改动。产出**编号的必修项清单**（`F-1`…），
   连同一份台账写进 `<git-dir>/review/<scope>.md`——台账跨轮沿用，编号不重新起算。
2. **判**：必修项清单为空 → 收敛，停。
3. **改**：非空 → 逐条改掉。
4. **验**：重跑受影响验证。
5. 回到 1。**同一套标准**，不是换一套更松的。

「收敛」的判据只有一条：**本轮必修项为空，且没有新增必修项**。它不等于「没发现
问题」（找不到与不存在是两件事），也不等于「测试通过」——测试只证明旧断言没被
破坏，证明不了新行为被覆盖。

## 分类

- **必修**：任一轴判「必须修复」的并集。不因为是「建议」就降级，也不因为「看起来
  不难」就升级。
- **建议**：不阻塞收敛，记成 follow-up 交回，**不需要问用户**。
- **假设**：拿不出证据的判断（「可能漏了某边界」）标 `[待实证]`，不计入收敛计数；
  要么补证据，要么写明为什么补不了。

## 停损

- 有一轴跑不了（范围解析不出、技能读不到）→ 写「无法评审」，不写「通过」。
- 轮次预算按 test-review 的口径；用完仍未收敛的项标 `⚠️ 待人工复核`，不当作收敛。
- 两个轴指向同一处却说法相反 → 以能拿出更具体证据的那一方为准，写出双方原话与取舍。

产物形态（结论几档、字段、怎么回流）按调用你的那份作业法，本技能不另立一套。
