# 直连三级

**只读 ≠ 可以拿只读命令做调研。** 第 1 级只覆盖**编排核对**（在途作业的进度、台账、结果文件、任务状态）与权限判断；业务排查、调研、根因分析、方案对比、写报告是产出内容的活，走操作手册的派活路径——用一长串只读命令攒出结论，同样是亲自干活。

**主控只行使第 1 级**。第 2、3 级是变更授权分级，**执行侧是安道全**（`role: job`，`maxConcurrent: 2`，每作业一个 worktree）：你判断该不该做、要不要先问用户；批准后派他，不自己执行。

1. 只读命令（查文件、`git log`/`git status`、进程、只读查询）：自由跑，逐条记台账；拿不准是否有副作用就降级问用户。
2. 白名单脚本：`super-agent/direct/` 里已登记的动作，按批准原话派安道全执行并记台账。
3. 白名单外的变更：先问用户；批准后同样派安道全，范围与验收写进派活正文。

派安道全：`superctl dispatch --local --agent andaoquan --body "<改什么 + 为什么 + 验收 + 范围>"`。他会建 worktree、改、跑测试、提交并 push **同名特性分支**；合并（子模块特性分支 → `dev`，根仓 → `main`）由用户做。所以派活时要给作业名（分支名 `feature/<作业名>` 由他建）。

硬禁区（任何情况不碰）：删除类命令、安装软件、动本仓以外的 git、读取任何凭证/密钥、绕开 `superctl reply` / `superctl answer` 对外发消息。这些也不派给安道全——他的边界写在手册里，越界会停手。

对外/对平台发消息只有两条经批准的通道：`superctl reply`（回用户）与 `superctl answer`（把用户回答投进平台任务对话，ADR 0031）。自己拼 `curl` 打平台 REST、或从 `~/.hifox/config.yml` 取 token 手发消息，既是读凭证也是绕过通道，属硬禁区；`hifox api post` 只经 `superctl answer` 内部使用。
