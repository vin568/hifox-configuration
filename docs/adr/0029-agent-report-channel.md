# ADR 0029：能力 agent 的主动回报通道

2026-11-19 的一次真实派活（HF-16139）暴露的是**主控被「等结果」占住**，不是派活本身慢：13:52:50 用户发来任务链接，13:53:42 就已经把活交给朱贵；但主控一直用 `bg` 轮询结果文件、`herdr agent wait`、`herdr agent read` 翻朱贵的推理，直到 13:59:12 才回用户。整段 6 分 22 秒里，真正干活约 40 秒，主控这一轮跑了 51 个 tool call——期间其他消息只能排队。

三条信号都缺一个「内容」通道：

- `working/done` 状态事件已经在推（13:55:36、13:58:51 两条都到了主控），但只说「状态变了」，不说「发生了什么」，`working` 还是纯噪声。
- 本地作业（石秀、朱贵）没有平台任务，平台哨兵永远不会为它们唤醒主控；它们的唯一信号就是 pane 状态与结果文件。
- 主控 → 能力 agent 的方向只能靠即兴的 `herdr agent prompt`（13:55:32 的重注入、13:57 的指令都是这么做），没有身份校验，也没有「消息是否被接受」的确认。

**决策：**

- **新增 `superctl report`（能力 agent → 主控）**：作业中的 agent 把卡点、需要裁决的事、用户可见的关键结果推给主控。注入信封是 `[触发器: agent] <agent 名>：<内容>`，与 feishu/event/sweep 并列；主控手册单列处理规则：这不是用户消息，需要拍板的用 `reply` 问用户，只影响编排的用 `tell` 回它。
- **新增 `superctl tell`（主控 → 本地能力 agent）**：中途补信息、或在巡检时问一句进度。目标 blocked 时 herdr 会在写输入前拒绝，命令如实失败并交回用户，**绝不替它按键**。
- **身份边界是在途清单**：只有 `superctl dispatch --local` 登记过的本地作业能 `report`，也只允许 `tell` 到这些作业。任意 pane 都能往主控注入「用户消息」是不接受的；`report` 不走 `ensureTopo`，能力 agent 不该顺手对账主控的拓扑。
- **完成仍以结果文件 + 状态事件为准**：`report` 只用于中途增量；`done` 事件附 `结果：<结果文件路径>`，主控不必猜写哪了。不要求 agent 再发一条收尾报告——那只会多叫醒一次。
- **状态事件降噪**：只有**在途本地作业**的 `done` / `blocked` 才注入主控；`working` / `idle`、常驻 agent（蒋敬的日常起动）与不在清单里的 pane 一律跳过。`blocked` 表示它卡在要确认的界面上，主控只上报用户。
- **派完即收轮**：`dispatch --local` 成功即写台账、回用户一句、结束本轮；后续由 `[触发器: agent]` 与 `[触发器: event]` 唤醒。巡检是兜底：在途本地作业超过一轮没消息，用 `tell` 问一句（同一作业每轮最多一次，连续两次没回音上报用户）。
- **投递必须确认**：`dispatch --local` 的首条 prompt 复用首条注入的送达校验（会话文件里出现结果路径才算落地，最多补三次 Enter，`blocked` 不按）；三次仍不落地就关掉 pane 并报错。**这是「收轮」的硬前置**：prompt 被吞而主控已经收轮，沉默会从 110 秒放大成 10 分钟盲区。
- **纪律放共享技能，实例事实留在注入**：`super-agent/capabilities/skills/agent-report/SKILL.md` 是共享能力技能（ADR 0025 的「位置即归属」），但**共享池不等于人人可见**：每个 agent 在 `agents/<key>/skills.yaml` 里声明自己要挂的共享技能（这是挂载清单，不是所有权——归属仍由目录位置决定，见 ADR 0025 的 2026-11 修订），运行时只挂载「至少声明了一个共享技能」的共享根，并用 omp 的 `ignoredSkills` 把同一根里未声明的技能挡在发现面外（一个都没声明就不挂共享根；`role: job` 必须声明 `agent-report`，`--check` 强制）。agent 的名字、runtime 绝对路径、结果文件路径是每次派活才确定的实例事实，只能由 `localPrompt` 注入——技能无法知道 `zhugui-055342` 是谁。注入里的 `[回报通道]` 段因此只给事实与命令，并指向该技能；新增作业 agent 时在 `skills.yaml` 声明一行即可，不需要改它的手册。
- **注入里的运行时路径必须稳定**：`runtimeCmdPath` 不再无条件用 `os.Executable()`——`go run` 的临时产物寿命跟着父进程，注进 prime 的路径下一次必扑空（实测主控第一次 `reply` 就撞上 No such file）。临时构建回退到仓库里构建好的 `super-agent/bin/superctl`，取不到就留空不打印。

**Considered Options：**

- **只靠 herdr pane 状态事件**：拒。事件没有内容，主控仍要读结果文件或 pane；对「卡住、要裁决」这类中途状态也表达不了。
- **让能力 agent 直接 `herdr agent prompt songjiang`**：拒。主控名是注册表派生的，命令里没有身份校验；原始文本还会被主控当成用户消息或事件。通道放在 `superctl` 里才有信封、闸门与在途清单边界。
- **给主控开一个通用 `herdr` 控制面**：拒。那等于把「替能力 agent 按键」的权限直接交给主控；`tell` 只允许发文本，且被 `agent_blocked` 挡住。
- **新增一条持久化 inbox 队列**：暂拒。herdr 本身就是常驻的传输层；主控 blocked / 急停时 `report` 如实失败，agent 落结果文件，巡检时补交。多一层队列会把「消息是否送达」变成第二种状态，当前规模不值得。
- **所有状态变化都注入**：拒。`working` 事件在事故里插进主控回合、什么也没带来；只保留 `done` / `blocked`，并限定在途作业。

**Consequences：**

- `superctl` 命令面多两条：`report`（agent 用）与 `tell`（主控用）；能力 agent 的派活注入多一段「回报通道」（自己的名字 + 精确命令 + 上报时机）。
- 主控的一轮从「派活 + 等结果」缩成「派活 + 记账 + 收轮」；用户可见的「已派出/已建单」由朱贵建单后立即 `report` 触发，不再等整轮跑完。
- **身份校验依赖在途清单**：agent 被提前 `cancel` 或清单被手改后，`report` 会被拒——这是故意的，错误信息要求把内容写进结果文件。
- 急停期间 `report` 静默（ADR 0020 的机器注入规则）；主控 blocked 时 `report` 失败并提示退路。两种情况下结果文件仍是最终载体。
- 通道不是「实时协作」：`tell` 只确认「agent 动起来了」（`--until working/blocked`，15 秒），不等回合完成；worker 正在长任务里时，消息要等它当前回合结束才会被看到。要中断用 `cancel`，不要指望 `tell` 抢断。
- 新增 ADR 后，主控手册、朱贵/石秀手册、`local-agents`/`platform-dispatch` 技能与 `tick.SweepPrompt` 都引用同一条纪律；漏一处就会出现「派了但没人报」或「报了但主控当用户消息处理」。
