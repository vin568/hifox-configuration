# 主控宋江与统筹入口吴用分面并存

吴用已是云端统筹中枢：飞书消息 → 主题判定 → 派堂/舵/任务 → 调度台账跟踪 → 转述，外加 30 分钟一次的台账巡检 automation（ADR 0002 / 0004–0012）。宋江的职责——本机 herdr 编排、云端任务下发、用户私人替身——与吴用高度重叠，不分界就会造出第二个吴用。

**决策：**

- **分面并存**：吴用管「人 ↔ 云端平台」的飞书对话与云端调度台账；宋江管本机 herdr 编排与用户私人代办（私聊全权 + 配置群的代答）。两 bot 两身份（各自独立的飞书自建应用），互不隶属。
- **边界一句话进双方提示词**：「飞书人机对话与云端产研调度找吴用；本机执行与我的私人代办找宋江」。
- **宋江的云端能力口径**：本仓 config 已声明的 agent 即全部云端能力，未声明即不存在；新增云端能力 = 加 config 声明（经用户批准后走本仓 git 与部署流程），宋江不自行改 config。
- **两套台账并存**：吴用的调度台账（事项）与宋江的作业台账（作业）各自独立、不互相同步；跨面引用只出现在用户对话里，由用户裁决归属。

**Considered Options：**

- **宋江吞掉吴用（飞书入口改指宋江，吴用退役或降级）**：拒。吴用体系是每日在产的生产契约；把人机对话与机器编排合并进一个大脑，迁移风险大且无对应收益。
- **宋江在上、吴用在下（云端活固定经吴用派发）**：拒。多一跳转述加延迟与失真；宋江本就直连 hifox CLI，委派即触发。

**Consequences：**

- 用户侧存在两个飞书入口，需要在人设与命名上可区分：宋江 = 私人替身入口，吴用 = 产研调度入口。
- 职责漂移由两侧复盘各管各面兜底：蒋敬的主控复盘只看作业台账，裴宣的夜间自省只看云端调度团队；跨面问题上报用户裁决。
