# 主控的 3h 整体审视与蒋敬的定时复盘

巡检从主控身上移走后（ADR 0044），主控只剩两种被叫醒的方式：用户消息与**需要处理的发现**。这留下两个节奏空档：

- 有些偏差不是单条事实，而是跨条目的趋势——积压老化（等待用户 >7 天、计划 >90 天）、同一作业反复失败或返工、巡检者本身是否失明/失准、直连记账是否漏记。这些每 10 分钟看一遍没意义（数据变化慢），但没有人定期看就会一直烂在台账里。
- 蒋敬的日度复盘目前靠主控「每天第一轮巡检顺手派」。巡检不再叫醒主控后，这个触发点消失；而它本质上是一个时钟事件，不该依赖主控恰好醒着。

**决策：**

- **主控整体审视 = 运行时按墙钟对齐的 3h 周期注入 `[触发器: review]`**。载荷带机器真值摘要（活跃台账数、在途清单、未投递发现、巡检者与哨兵健康）。`state/review.json` 记 `last_review_at`，重启后错过的整点不补，下一整点做。
- **审视只看「面」，不重做逐条对账**：积压与老化、同一作业反复失败、巡检者准确性与存活（抽查 1–2 条它标的「最近核对」）、直连记账粗筛。逐条真值归巡检者；只有确认巡检者失明时，审视当场接管一次全量核对并上报用户。
- **审视的输出纪律**：干净时只写 `state/reviews/current.md`（一行确认，证明它真跑过）并 append 到月度归档，不打扰用户；有需要处理的事项才按发现闭集私聊用户，同一轮最多一条。
- **蒋敬改为运行时定时触发**：新增 `retro_at = "02:00"`（本地时区），`state/retro.json` 记 `last_fired_date` 与结果路径；第一个跨过该时刻的 tick 派发一次，serve 宕机后自动补跑。窗口为前一日 00:00–24:00。**不复用 3h 审视**——那会把派发权留在主控手上，且两套节奏互相污染。
- **蒋敬的产物只有一个读取点**：审视。蒋敬跑完完全静默（`done` 不注入主控、不 `report`），结果路径写进 `state/retro.json`；审视比对 `last_result` 与 `relayed`，只对没见过的结果转述一次，然后 `superctl retro ack` 写 `relayed`。临时派给蒋敬的复盘（主控自己派的）不进这条链，不参与转述；派发层用「静默投递」（`inflight.Entry.Quiet`）区分定时轮次与临时作业。
- **健康复核**：审视与蒋敬复盘都读 `state/inspector-health.json` 与 `state/sentinel-health.json`；巡检者连续 3 个 tick 无成功轮次由运行时立即告警（ADR 0044），审视只做二次确认，不替代它。

**Considered Options：**

- **3h 用纯 interval（从 serve 启动起算）**：拒。重启即漂移，「上次审视是什么时候」要查日志才能回答；墙钟对齐是给人看的节奏。
- **框架里实现五段 cron 解析器**：拒。当前依赖只有 toml / yaml / 飞书 SDK，为「每日 02:00」引入 cron 的全部语法与用例不划算；`retro_at = "HH:MM"` 的日界语义足够，而且天然表达「前一日」窗口。
- **让蒋敬自己排期，或让巡检者每 3h 派蒋敬**：拒。两种都把「谁叫醒谁」倒挂；运行时是唯一时钟源。
- **蒋敬有提案时 `superctl report`，审视只确认已跑**：拒。两个读取点必然出现重复转述（02:xx 报一次、03:00 审视再读一次），去重只能靠主控记性；单读取点由结构保证不重复。
- **审视每轮重做全量对账（天然兜底）**：拒。8 次/天 × 全量的上下文成本与巡检者重复，且会训练主控忽略巡检结果；按需接管更省。
- **无发现也私聊用户「一切正常」**：拒。8 次/天纯噪声；写文件足以证明审视在跑。

**Consequences：**

- 主控醒来后要区分三种来源：`[触发器: sweep]`（发现，需处置）、`[触发器: review]`（整体审视，通常只写文件）、`[触发器: event]`（平台哨兵/本地作业事件）。框架触发闭集与主控契约同步扩展。
- 审视的「干净」定义必须可核对：`state/reviews/current.md` 每轮一行，蒋敬复盘与 3h 审视都读它；否则「审视是否真跑了」会退化成日志考古。
- 蒋敬虽改为定时，仍保留 `role: retro` 的常驻与单并发语义；主控临时派它做专项复盘的能力不变，只是产物不进自动转述链。
- 每日 02:00 + 3h 审视 + 10m 巡检 + 60s 哨兵共四个节奏，全部是运行时配置（`tick_interval` / `review_interval` / `retro_at` / `platform_poll_interval`），不新增声明面。
