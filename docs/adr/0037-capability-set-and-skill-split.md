# 能力集：技能是能力单元，agent = 身份 + 能力集

行为文本长期集中在各 agent 的 `instructions.md`，共享技能池里唯一常住成员是框架强制的 `agent-report`——真实的跨 agent 共享为 0。结果是：加一项能力 = 改手册；两个角色需要同一套方法 = 复制；手册越写越长，关注点混在一起。框架 ADR 0007 把机制文本移回注入后，手册只剩身份、边界与判断，能力可以独立成技能。

**决策：**

- **能力单元 = 一个技能 = 一个触发场景**。agent = 身份 + 岗位手册 + 能力集（`agents/<key>/skills/` 的全部专属技能 + `skills.yaml` 声明的共享技能）+ 运行参数（workspace / kind / args / maxConcurrent）。给某人加一项能力 = 改挂载，不改手册。
- **拆分规则**：
  1. 一个技能只服务一个触发场景；总是一起加载的两个技能合并，不为拆分而拆分。
  2. 技能正文不复制事实：路径、命令、参数以框架注入或 CLI 自描述面（`--help`）为准。
  3. 两个以上 agent 之间的接口（如派活信封的字段）抽成**协议技能**，需要它的双方各自显式挂载；不复制、不隐式依赖。
  4. 技能之间可以引用，但必须写成 `[[skill:<name>]]`，检查器校验该技能存在且对当前 agent 已挂载——没有隐式耦合。
- **路由仍按 agent key**：`superctl dispatch --local --agent <key>` 不变；候选不唯一时由主控判断。索引给两个视角：「本地能力」段每个 agent 下列一行 `能力集`（专属 + 声明共享），「技能」段写「共享 → 谁」。框架不新增 `--capability`——挑人与并发/幂等语义是主控职责。
- **强制引用**：手册里引用技能只用 `[[skill:<name>]]`；`npm run check` 校验存在性与挂载范围。选中判断交给技能自己的「何时用」，不够就改 description，不往手册堆解释。
- **防漂移门禁**：`npm run check` 拦三件事——① 同一规范化正文行（≥24 字）在两处重复，范围含 `SKILL.md` **与手册**（标题、代码块、frontmatter 不参与比较）；② 同一字段的闭集声明（`字段：甲 | 乙 | 丙`）出现两次；③ 手册与技能里写死的机器绝对路径（`/Users/…`、`/home/…`）——路径是机制事实，只该出现在首条注入里。逐字比较拦不住改写过的漂移，闭集规则是补它的那一半。
- **范围**：先落本地运行时（`super-agent/capabilities/`）。平台侧 `config/<集合>/agents/*/skills` 由 x-deploy 管理，维持 ADR 0010 的 `dir: @/skills/<名>` 私有实例模型，另案统一。
- **术语**：单位叫**能力技能**（一个技能），集合叫**能力集**（某 agent 挂的技能）；「能力」裸词停用，避免和「能力 agent」「能力注册表」混读。
- **迁移**：删 `agent-report`（框架 ADR 0007）；从各手册删掉 checkpoint、结果文件、回报通道的复述段；主控三份技能按触发场景复核，不强行再拆；共享池首批成员是 `dispatch-envelope`（协议技能）与 `direct-tiers`（主控与复盘者共同挂载的审计判据）。

**Considered Options：**

- **全量技能化**（手册只留身份一行）：拒。常驻契约按需加载会掉遵守率（ADR 0010）；机制文本已归注入（框架 ADR 0007）。
- **能力 = agent 的职责，共享只共享文本**：拒。那是现状，真实多人具备为 0，手册继续膨胀。
- **新增 `abilities/` 注册类型**：拒。技能目录已能承载能力（位置即归属 + 挂载清单），加类型就多一份真源。
- **框架按能力路由（`--capability`）**：拒。见上；等出现第二个真实持有者且主控挑不动时再议。

**Consequences：**

- 能力集成为一等视图：看索引就知道谁会什么；同一技能挂给多个 agent 即「多人具备」。
- 技能数量上升带来选中噪声与加载成本；由「总是一起加载就合并」和 description 纪律兜底。
- `[[skill:]]` 是手册里唯一的技能名表面；技能改名必须同步手册引用，漏改会被检查器拦下。
- 同一段正文复制到两个技能会被门禁拦下；确有必要的重复要合并或上移为注入/协议技能。
- 本地与平台两套技能形态（元数据规则不同）仍然并存，跨侧搬运需改 frontmatter（框架 ADR 0025）。
