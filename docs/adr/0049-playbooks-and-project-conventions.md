# 0049：作业法与项目约定——把「怎么干」和「这个项目的事实」从手册里分出来

本仓的本地运行时只有两个 job 角色：石秀做只读调研，安道全做本仓维护。一旦安道全要服务多个项目（`xwing`、`x-deploy`、将来的 apifox 各仓），他的手册就会把三类东西混在一起：身份与边界（「你是谁、不许做什么」）、方法（「怎么干」）、本仓事实（「子模块在哪、测试怎么跑」）。第一类换了项目也不变，第二类换项目不变、换任务类型才变，第三类一换项目就变。手册里每加一个项目就复制一份流程，这与部署侧「一个项目一个交付 agent」是同一个膨胀机制，只是发生在本地。

**决策：**

- **三层切分**：agent（身份 + 边界 + 收尾）、作业法（怎么干）、项目约定（这个项目的补充与覆盖）。判据：**角色换了才变 → 手册；任务类型换了才变 → 作业法；仓库换了就变 → 项目约定**。
- **作业法是派活期指定、内联注入的第四种注册类型**（机制见框架 ADR 0024）：`super-agent/capabilities/playbooks/<key>.md`，在 `agents/<key>/playbooks.yaml` 声明，`superctl dispatch … --playbook <key>` 选中。它不是技能：不进模型的选择面。
- **v1 只落三条**：`dev-loop`（交付：定标准 → 取证/复现 → 计划 → 实现 → 自验 → 自审 → 提交与汇报，自审不过回流到实现）、`investigate`（只读查清事实，产物是报告）、`review-diff`（对一段 diff 给分级结论，禁改代码）。`dev-loop` 的取证阶段与自审阶段分别以 `[[playbook:investigate]]`、`[[playbook:review-diff]]` 引用另外两份，由框架静态展开。
- **持有者**：安道全声明 `dev-loop` / `investigate` / `review-diff`；石秀声明 `investigate`。石秀的手册保留自己的只读边界与收尾，调研方法只留一份。
- **8 条作业纪律进框架角色契约**（证据/复现/验证/裁决/范围/环境/审查/预算）：它们换项目、换作业法都不变。手册与作业法都不复述——逐字重复门禁只拦完全相同的行，改写一遍拦不住，靠评审不靠机器。
- **项目约定是可选补充**：`super-agent/capabilities/projects/<key>.instructions.md`，注入为 `[项目约定]` 段。它只放仓库文档没有的机器事实与显式覆盖（`覆盖：<原约定> → <新约定>，理由…`）；文件缺失合法，事实以仓库自己的 `AGENTS.md` 为准。`hifox-configuration` 的首份内容只有四条补充（worktree 脚本、mise 的 go、`npm run check` 需要 yq、分支与合并归用户）。
- **安道全手册瘦身**：仓库名、子模块列表、`npm test` / `go test` 命令、集成分支名、gitlink 顺序全部下沉到项目约定；手册只留身份、成功判据、三层阅读顺序、边界、收尾与结果骨架。
- **`maxConcurrent` 改为「能力 + 位置」计数**：修订 ADR 0042 的「按人跨所有位置」。多机器的意义是加吞吐；一个全局数字会把它抵消。单机内的保险丝保留，旧条目按 agent 名前缀兜底认领不变。
- **检查面扩围**：`check-registry.mjs` 的重复正文与闭集检查覆盖 `playbooks/` 与 `projects/*.instructions.md`——从手册搬出去的事实会落在这里，不扫等于让「一个事实只许有一份」在最容易长第二份的地方失效。
- **已识别、未落地**（出现真实持有者再写，判据是阶段顺序或回流方向不同）：`incident-mitigate`（先止血后根因）、`refactor`（先建行为基线再变换）、`black-box-accept`（对已构建产物判定达标并留证）、`greenfield`。只改「用什么证据证明」的（迁移状态矩阵、兼容矩阵、性能基线）留在项目约定，不是新作业法。
- **边界**：作业法只管本地与执行节点通道；平台派活拒绝 `--playbook`（部署侧 agent 的方法写进它自己的 `instructionsFile`）。`config/` 侧的 agent 收敛是另一条设计线，本 ADR 不承诺。

**Considered Options：**

- **作业法做成技能**：拒。技能挂在模型发现面上，description 决定「要不要读」，把一次确定的派活选择降级成模型判断；同一份文件还会同时被派活注入与模型自行加载，两条路径指向一个 key。
- **保留在手册里、只做文档整理**：拒。石秀已有的调研方法一被安道全复用就要复制，复制点正是重复正文门禁要拦的地方。
- **项目约定放仓库 `AGENTS.md`**：拒。等于要求每个被开发的项目先有一份合格文档；而且注册表侧的补充（机器路径、本机工具链）本来就不该进项目代码。
- **项目约定做成 `projects/<key>.yaml` 的字段**：拒。该文件严格解析，加字段会让旧二进制整份失败；旁挂 `.instructions.md` 对旧二进制不可见。
- **一次落满 7 条作业法**：拒。没有持有者的流程是编造；`incident-mitigate` 与 `refactor` 在现有 15 份手册里都没有阶段序列，只有「需要单独授权」的条款。

**Consequences：**

- 安道全从「本仓维护员」变成「通用开发作业 agent」，`description` 已同步；石秀保留只读身份，得到 `investigate` 一份共享方法。
- 注入顺序变为：契约 → 经验 → 手册 → 作业法 → 项目约定 → 任务。后两段可空，未指定时一个字都不加；8 条纪律是有意新增的常驻文本，整份注入因此不与旧版逐字节相同。
- 作业法与项目约定都是实例内容，框架只提供注册、展开与注入；框架的通用性不因为「多了一个项目」而变化。
- 加项目 = 加 `projects/<key>.yaml` + 检出表 +（可选）`.instructions.md`；加方法 = 加一个 md + 一行声明。都不改手册。
