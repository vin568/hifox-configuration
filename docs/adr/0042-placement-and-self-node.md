# ADR 0042：择节点与可选本机节点——机器指标准入，不做运行时再均衡

`super-agent/capabilities` 随仓分发到多台机器；每台机器的运行时配置（检出、`state_dir`、herdr session）是本机的，主控可以跑在任意一台上（同一时刻只有一台）。机器之间由用户维护的同一内网（Tailscale 等）保证连通。预计同时运行的 agent 数会上升，单机内存、CPU、磁盘可能成为继续派活的阻碍。ADR 0041 的「本地 herdr 是隐式节点、只有远端写声明」不再成立：本机也要能声明成节点，才能进入自动择节点。

**决策：**

- **执行面三态**：隐式本机永远存在；已声明节点是显式位置；本机节点可选。声明了且标识匹配 = 本机节点，与远端节点平权进入自动择节点候选；没声明 = 本机仍可显式 `local` 派活，但不进候选池。
- **`local` 是保留符号**：声明了本机节点时解析成该节点的 key，否则保持字面 `local`；不得再用作普通节点 key。实现上，本机执行仍在在途清单里保留空 `Node` 哨兵——`state_dir` 按机器隔离，空串已经唯一指向本机，自造第二套本机身份只会让 8 处监督路径同时判断「空串 / local / 本机 key」三种写法。`local` 与本机节点 key 在派活入口互相解析，落到存储仍是同一个哨兵。
- **节点标识**：节点声明新增 `identity`（macOS `IOPlatformUUID`、Linux `/etc/machine-id`）。运行时用自身标识在 `nodes/` 中找自己；找不到是合法状态（没有本机节点），同一标识声明两次是校验错误。hostname 只作显示名。
- **本机节点强一致**：本机节点的 `state_root` / `work_dir` 与 `session` 必须等于运行时配置（展开 `~` 后比较）；不一致即报错。`instance_root` 已由 ADR 0043 删除。`machine` profile 只用于远端访问，本机不走 `--machine`；`check:live` 跳过本机节点。
- **位置策略**：agent 声明 `placement: auto`（默认）或 `pinned`。`pinned` 的能力必须显式 `--local` / `--node`，用于「去某台机器本身就是任务语义」的调研类作业。
- **自动择节点是派活时的负载均衡**：`dispatch --auto` 只在 agent 的 `targets` 覆盖的已声明节点里选；派活前按节点声明的 `limits` 过滤——可用内存比例、每核 load、该节点 herdr 可见的 agent 数（整机，含非本实例进程）、可用磁盘比例；越线跳过，全部不合格 fail closed 并列出各节点原因。候选按该节点在途数最少排序，平手按 key 序。采样在派活时进行（本机直读、远端固定只读 ssh 探针）。这就是本模型的负载均衡：发生在准入时刻，不做运行时再均衡，也不迁移已在跑的作业。
- **派活串行化**：选择与登记在同一把锁内，避免两个并发派活同时把作业投到同一台「看起来空闲」的机器。
- **并发预算仍按人**：`maxConcurrent` 按能力 key 全局计数（跨所有位置）；机器容量由 `limits` 管，不拆成按节点计数。
- **单主控**：同一时刻只有一台机器跑 serve/主控；`state_dir` 就地，不共享；换机是人工停/起。共享状态与多主控留到确需时另议。

**Considered Options：**

- **要求每台机器都声明本机节点**：拒。本地节点可选；不声明时显式 `local` 仍然工作，配置更简单。
- **节点声明写 `self: true` / 用 hostname 判断**：拒。前者破坏 capabilities 跨机器共享，后者会因改名或重名误判。
- **找不到本机节点时回退到隐式本机池**：拒。静默改变落点；未声明就不参与自动选择。
- **按节点拆 `maxConcurrent`**：拒。预算是「一个人同时干几件」，不是机器容量；拆开会让加机器等于放大模型配额消耗。
- **运行时再均衡 / 跨节点迁移**：拒。产物与副作用锚在节点文件系统；ADR 0041 的失败语义是 fail closed，不自动重派。
- **多主控或共享 `state_dir`**：暂拒。飞书长连接只能有一个所有者，两套在途清单/台账无法对账。

**Consequences：**

- 节点 schema 增加 `identity` 与 `limits`；框架 `--check` 校验标识唯一与 limits 数值，本机节点的路径与会话在读取实例配置的 `capabilities --check` 与派活入口校验（`npm run check` 用 `--root` 检查检出，不比较本机运行时配置）。
- 在途清单仍以空 `Node` 表示本机执行面（实现细化见决策 2）；监督路径不改判据，`local` 与本机节点 key 只在派活/管控入口互相解析。
- `nodefs` 增加固定只读指标探针（不开放通用 shell）；指标读不到 = 该候选不合格。
- 指标是派活时刻的快照，只阻止新作业进入过载机器；已在跑的作业不会被搬走。
- 机器上的非 super-agent 进程（用户自己的 omp、构建）计入容量；这是整机口径。
- ADR 0041 的「本地隐式、只有远端声明」由本 ADR 取代；寻址制、节点不持有在途清单、outbox、事件与 fail closed 仍然有效。
