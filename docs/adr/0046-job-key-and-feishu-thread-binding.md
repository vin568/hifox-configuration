# ADR 0046：作业 key 与飞书任务话题

宋江在飞书里提到多个作业时常用「那张单」「那个事」，任务一多就指认不清；提到机器时也只说「那台机器」。同时，一个作业的后续讨论散落在主区、不同话题与私聊里，换脑或重启后接不上。2026-11-27 定下两件事：**作业 key 是唯一引用标识**；**作业在第一次带 key 的回帖时懒创建一条飞书话题**，后续更新回到该话题。

## 决策

### 1. 作业 key

- 规范形 `<命名空间>:<id>`。平台作业的命名空间 = 平台 CLI 应用名（`hifox:HF-16434`，将来 `sharkly:...`）；本地作业 = `job:` + 作业台账文件名去扩展名（`job:20261126-漏报与漏回话机制修复`）。
- 命名空间是闭集：`capabilities/platforms/` 下的目录名 + `job`。**未知命名空间直接拒绝**；解析层只守结构安全（非空、无控制字符 / 空白 / 冒号 / 括号 / 路径分隔符），大小写与下划线由闭集判。`reply --key` 不接受裸 id（提示补命名空间）。`id` 整段不解析，只做非空、长度、控制字符、空白、路径分隔符、冒号与括号检查（后两者是 Markdown 链接与 key 分隔符的安全边界）。框架不校验 `HF-` 之类的前缀形状——hifox 的任务前缀由每个 Space 自定且唯一，运行时不解析。
- `id` 只做尽力核对：平台 key 查在途清单（归档任务查不到属正常，仍写 `key-unresolved` 提示引用可能指向已归档的单），`job:` 查台账 active/archived 文件名；查不到**不拦发送**。绑定表以完整 key 为唯一键；同一 key 出现不同会话/话题的绑定时写 `key-conflict` 发现，不静默覆盖。
- 对话显示短 id（平台任务 `HF-16434`，本地作业台账短名）；完整 key 用于绑定、注入与台账键行。平台任务的短 id 在主人面与成员面都以可点击链接呈现。
- 主人面与作业台账提到作业即带 key/链接；群成员询问本群在途任务进度时也回短 id 与链接。本地作业 key、节点 key 与 agent 名只在主人面与台账出现，群/成员面不出现。
- 机器引用统一 `name（key）`（如「工作机 1（dev-mbp-1）」）；节点 key 是能力注册表标签，不是机器标识（ADR 0008 修订）。

### 2. 话题绑定

- `state/threads.json` 一条 = 一个完整 key：`key`、`chat_id`、`thread_id`、`root_message_id`（触发消息）、`anchor_message_id`（话题内第一条回帖）、`url`、`title?`、`degraded?`、`created_at`、`last_used_at`。绑定是机器真值，不放进 inflight：收口、归档、换脑、重启都不删。
- 懒创建：第一条带 `--key` 且带显式锚点（`--reply-to`）的出站回帖，用 `reply_in_thread=true` 回复锚点消息；drain 成功后从 reply 响应的 `thread_id` 落绑定。触发消息本身已在话题里时，飞书回执直接给出该话题 id，新作业随之绑进同一话题，不另开。没有锚点不建话题；无锚点且无绑定的 keyed 回帖按普通发送，写 `thread-degraded` 发现（要建话题却缺锚点）；`--admin` 永不建话题。
- 一条触发消息派生多个作业时共享同一话题：消息里只要有任一个 key 已绑定，就以它的话题为准，其余 key 收敛过去。不额外发任务卡。
- 后续主动更新：不带 `--reply-to` 时按绑定投进话题（reply 到 `anchor_message_id`，缺失回落 `root_message_id`，仍带 `reply_in_thread` 兜底）；显式 `--reply-to` 永远优先——用户在主区问就在主区答，哪怕该 key 已有话题。显式锚点回复**不改写**已有绑定（话题的家不随一条就地回答搬家）；只有该 key 还没有绑定时才借这条锚点建话题。锚点所在会话与已有绑定不同时，会照常建出新话题，但**不覆盖**旧绑定，并写 `key-conflict` 发现。
- 话题不存在、被删或锚点失效 → fail-open：退回普通发送，绑定标 `degraded`，写 `thread-degraded` 发现，不重试建话题；消息优先，话题是增强。
- drain 按 key 串行，避免同一 key 并发开出两个话题；绑定写失败不回滚已发出的消息。
- 入站命中绑定话题时，注入加 `<job key="..." title="...">`；`group_tasks` 带短 id、链接与备注。`--admin` 与无锚点消息不参与建话题。

### 3. 链接渲染

- 飞书不支持 HTML `<a>` 标签；文本消息原生支持 `[短 id](url)` 超链接。尾行用它，不用 post。
- 正文已有该短 id 的 Markdown 链接则不补；平台 key 的 URL 未知 → 补 `—— HF-16434` 并写 `key-no-link` 发现（本地作业 key 本来就没有链接，不写该发现）；多个 key 合成一行，` · ` 分隔。补尾行的触发条件是「这条回帖带 `--key`」——主控用 `--key` 声明这事与某作业有关，正文没提也照样补（指认是声明，不是文本巧合）。
- URL 解析顺序：`--link` > 绑定表缓存 > 在途清单 `url`。`--link` 只允许与恰好一个 `--key` 同用；多 key 走缓存。
- `dispatch`（平台 / 本机 / 执行节点三种通道）与 `track` 的结果新增 `key` 字段，并写在途 `url`；台账骨架写 `- 作业 key：...` 与链接；`track` 新增可选 `--url`，不联网取真值。

## 实现分工

- **框架（`vendor/super-agent`，机制决策见框架 ADR 0022）**：`reply --key/--link`、outbox 条目 key、sender 的 `reply_in_thread`、`threads.json` 读写与按 key 串行、注入 `<job>`、`group_tasks` 与 inflight 的 `url`、去掉任务号形状校验、dispatch/track 输出 key、`threads list/prune`（list 只读、可带 `--key/--json` 过滤；prune 必须显式 `--older-than`，可 `--dry-run` 只数不删）。
- **平台侧命令保持裸任务号 + `--platform`**：`dispatch --update`、`answer`、`cancel`、`track --task` 不解析命名空间；完整 key 只出现在 `reply --key`、注入与结果输出里。
- **实例**：ADR、GLOSSARY、手册/技能、台账骨架文案。**代码落地前手册不改命令示例**，避免主控调用不存在的 flag。

## Considered Options

- **裸任务号当 key**：拒。前缀由 Space 自定，本地作业没有号，跨平台会歧义。
- **`--task` / `--job` 两个 flag**：拒。把平台业务写进框架；用户要求单参数。
- **先发任务卡再开话题、一作业一话题**：拒。多一条主区消息；一条消息派三张单时共享话题更自然。
- **绑定放 inflight**：拒。收口即删，归档后接不上。
- **fail-closed（没建成话题就不发）**：拒。话题是增强，不能成为投递单点。
- **运行时按平台拼 URL**：拒。框架不认平台语义；URL 只作不透明缓存。

## Consequences

- 成员面可见平台任务短 id 与链接（ADR 0038 修订）；内部 agent、workflow、机器 key 仍不出现。
- ADR 0008 增加节点 key 例外；ADR 0039 增加按作业懒建话题的修订；ADR 0040 的来源匹配扩展到绑定话题，并在在途清单新增 `url`。
- 框架去掉 `taskIDPattern` 这类前缀形状校验；脏 key 由平台回执兜底。
- 框架的发现闭集新增 key/thread 类：`key-unresolved`、`key-no-link`、`key-conflict`、`thread-degraded`（ADR 0015 的发现机制不变，只扩类别）。
- 群里的作业话题对群成员可见；话题内的主人消息也遵守成员面边界（不写节点 key、agent 名、workflow）。
- 吴用的对外口径不变；本 ADR 只作用于宋江实例。
- 落地顺序：框架先、实例手册后（本次已按此顺序实施）。

**依据：** 本仓 ADR 0008（密钥与机器标识）、0016（宋江运行时）、0038（群边界与发送者身份）、0039（话题与回复锚点）、0040（任务来源）；框架 ADR 0012（私聊话题信封）、0014（漏回）、0015（发现）、0022（回帖 key 与作业话题）。
